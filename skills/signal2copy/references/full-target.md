# Signal2Copy functional baseline — 18 November 2026, revision 1

## Authority and scope

This is the behavior target for the next `signal2copy` skill, approved for baseline preparation on18November2026. It consolidates the current Signal2Copy product, including implemented changes through FB-033. It does not update skill0.3.5 or assert that a new generated application exists. Use feature-map.md for coverage, workflow.md for the guided increments and baseline.json for provenance. This bundled reference is self-contained; original product files are not required.

For this successor, this consolidated contract supersedes conflicting historical prose in the November10 kit and product change log. Historical artifacts/results remain valid for their own versions. Subsequent product changes do not silently move this target: record a new explicit baseline revision and its delta.

Functional identity means equivalent supported user actions, business calculations, state transitions, access boundaries, failure/recovery behavior and outputs. Source code, internal routes/schema/language and exact CSS/screenshots need not match. Use a clear responsive English interface with light/dark themes, accessible controls and readable numbers/errors. Preserve meaningful labels/semantics; do not spend a parity budget on pixel matching. The product displays Signal2Copy unless its recipient requests another name; all deployed resource names/secrets belong to that recipient.

The scope includes the client application, unattended broker executor, persistent Cloudflare deployment, separate owner console, role-specific user guides and operation/restore instructions. Current user accounts, positions, subscription settings, secrets and individual past trades are not baseline inputs or seed data. Current policy values do not override clean-install defaults.

## 1. Identity, onboarding and strategy publication

- One provider per installation. Before registration show provider registration, not investor entry/catalog; server blocks investor access too. Require temporary invitation plus verified Partnership API/private Ed25519 pair. Consume registration only after successful verification and atomic registration; later provider login needs the registered pair, not the invitation. Invitation changes alone do not reopen registration.
- Unified sign-in determines role from verified keys, without a role selector. Registered Partnership keys identify Provider even if also Trading-capable. Foreign Partnership credentials do not gain provider access or fall back to investor. Trading-only keys require successful verification of one supplied account before session creation. Known Partnership-scope denial differs from unknown/auth/signature/network failure; an unavailable capability check must not create an investor session or downgrade the provider.
- Investor has no separate registration and one account per session. Server checks role/account ownership on every private read/mutation; subscription state is independent of browser session. Use secure HTTPS cookies, mutation Origin/CSRF protection, safe validation/rate limiting and encrypted server credentials. Do not echo keys/signed requests, place secrets in URLs/browser storage or share one client's market data with another.
- Provider sign-in keys are retained encrypted with disclosed consent and reused for authorized provider features, never requested again in Copy settings. Historical fingerprint-only sessions may reuse an identical vaulted pair or require one normal re-login. Source Trading credentials remain a separate verified account connection; Partnership access alone does not grant source access. First-setup key handoff, when applicable, is tab-memory-only and cleared after connection/logout/reload.
- Guide the provider through source connection, account/history verification, strategy creation, publication and later unpublication. Multiple strategies use dedicated source accounts, one source per strategy. Source activity on that account is strategy activity. Read account/position/order/history state; do not place a test order to validate read access. Provider can inspect source history, subscribers, strategy filters/counts and role-specific reports. Unpublication blocks new entries without abandoning management of existing copied exposure.
- After registration, expose published catalog/details publicly: description/risk, observed performance/equity and verification/coverage, history/current source exposure, subscriber count and Sign in to copy. Do not imply observed history guarantees returns. Retain selected strategy through investor login/connection. Existing unfinished subscription opens its existing state rather than creating a duplicate request; successful Start/saved activation navigates to Subscription, even if its subsequent refresh fails.
- Authenticated catalog/detail includes Copy strategy link using current origin plus encoded public strategy ID, with no query/private/session data, no nested navigation control and no API mutation. Announce Link copied only after clipboard success, for2.5seconds. Missing/denied clipboard offers selected read-only URL/manual instruction and Close/Escape focus restoration. Anonymous portal is unchanged by this action; messenger/native Share is not implemented.

## 2. Subscription and sizing

- One unfinished subscription reserves an investor account: active, paused, stopping and awaiting activation. Stopped permits a new subscription under current readiness rules; signing out and Pause do not release it. Explicit connection is separate from explicit Start; no trade begins from login, preview or example interaction.
- New setup defaults to Proportional and Copy new trades only. Initial scope must be explicitly confirmed. Include current exposure uses a fresh source snapshot: market positions at current executable prices, pending orders at current levels; do not replay closed history. Pause cancels unfinished initial entries and Resume does not rerun initial catch-up or replay entries created while paused.
- 1:1 preserves exact source lots, multiplier1; incompatible broker min/step/max blocks rather than silently resizing. Activation saves a risk-calculation budget from verified investor equity, capped at10,000 native units and floored to two decimals; this budget does not rescale lots.
- Proportional lots = source lots × allocation × investor-to-source currency rate ÷ current positive source equity × multiplier. Allocation is positive, at most verified investor equity, up to16digits/two decimals, with no nominal10,000 cap; multiplier0.01–2. Allocation is a sizing input, not a wallet, reserved funds or total exposure/loss cap. Multiplier1 does not imply equal lots.
- Round Proportional lots down to the investor step. Below minimum: skip with evidence, never round up. Compare rounded lots to allowed maxima; skip excessive volume, never clamp. Equity changes alone do not resize established copies. Record original source equity/FX, raw/rounded lots and conditions used for each decision.
- Editable hypothetical sizing example uses cached verified inputs; it does not authorize execution, send broker requests or become order settings. Missing equity/FX/conditions is explicit; a successful example is not a fill/margin guarantee.
- While Paused, edit mode and Proportional amount/multiplier, including remaining in the same mode. Prefill saved values, reset consent after any edit, atomically save/audit without Resume or broker writes. Above-equity/invalid input makes no partial save. Old clients omitting parameters preserve saved Proportional values. Switching to1:1 keeps budget and resets multiplier1, rejecting Proportional-only parameters. Existing mappings keep recorded sizing; future eligible entries use new parameters after separate Resume/readiness. Show enabled daily-loss cash-threshold consequences.

## 3. Broker integration, FX and execution

- Implement real Exness Trading/Partnership adapters separately from the deterministic synthetic broker. Use supported signing, account access-point discovery, account-scoped REST/stream data and quotas/backoff. Verify capabilities, matching instrument contracts, fresh account/transaction state, permissions, broker volume, margin and exposure before dispatch. Source observation needs contract specifications, not an unnecessary source margin-FX stream.
- For eligible new signals copy Buy/Sell market entries and all four Limit/Stop pending types; propagate repricing, SL/TP updates and independent/both-level removal, partial/full closure and pending cancellation. Pending placement is not a fill. Attribute fills/residuals only by exact request/order/position evidence, including partial fills; do not duplicate a market entry after a pending fill. Track actual confirmed mapped lots and anchor partial reductions rather than repeatedly applying ratios or touching unrelated exposure.
- Observe source changes consistently: if source changes during target observation, re-observe/defer the stale decision, never close/reopen from an invalidated view. Do not claim an atomic multi-account broker snapshot.
- FX supports same-currency rate1, direct/inverse and bounded fiat cross routes. Selling base uses Bid, reverse uses1/Ask; multiply cross legs. Prefer valid tick-only routes, usable live/original last ticks; account-scoped trading-disabled fiat instruments may value currencies but remain prohibited for trading. Do not place exchange orders or invent external/manual rates.
- When conversion ticks are unusable, use validated broker Bid/Ask candle references: M1 preceding hour, then D1 preceding seven days. Positive finite Bid≤Ask, nonfuture original candle open time, age≤7days. Preserve `broker_candle_close`, reference-only flag, timeframe/open time and unknown exact last constituent tick time; never relabel as a fresh tick. Actual ticks supersede references, older references cannot overwrite newer evidence. Allow mixed tick/reference routes; exclude non-fiat bridges and the actual traded instrument from executable-price fallback.
- Cache positive/negative candle results60seconds per account/instrument; retain normal30-second readiness-report reuse. Quota/access/transport errors keep normal recovery, not silent D1 retries. Missing conversion remains unavailable with route/timestamp/cause evidence. The traded instrument still requires an actual executable tick≤5seconds, synchronized transactions and independent permission/margin checks. Disclose conversion provenance in readiness and volume calculation.
- Persist exact intent/request identity and dispatch evidence durably before broker writes. Durable acknowledgement failure stops writes. ACK is not a fill. Proven pre-dispatch transient failure may retry with backoff; synchronous terminal refusal remains terminal. Transport/malformed success/uncertain server error or operation404 is not proof of no execution. Never blindly resend an ambiguous write, including after restart.
- Hold uncertain related source groups/exact exposure, not all independent commands. Independent groups, including on the same instrument, can continue after fresh checks; conservatively reserve uncertain margin/slots. Broader identity/account ambiguity remains protective. Broker results require exact correlation, not approximate matching.

## 4. Lifecycle, controls and recovery

- Pause blocks new entries, cancels copied pending entries/unfinished initial opens, and retains authorized management of already copied positions. Preserve Pause across restart. Manual Resume uses fresh checks/one confirmation; do not replay paused history. Routine recovery does not override explicit Pause/Stop, admission, publication or permanent/protective holds.
- Stop blocks entries and normally closes/cancels only confirmed subscription-owned exposure; manual/source/unrelated exposure is untouched. Reconcile boundedly: if unresolved results prevent verification, allow Stopped with permanent broker-follow-up, preserving uncertainty and investigation evidence. Stopped does not mean account flat and never permits resending unknown commands. Archived investigation-only commands do not alone block a new subscription. Known rejected cleanup retries require fresh exact-exposure confirmation; ordinary result recovery needs no repeated consent.
- Five optional Advanced controls default OFF/null: entry-price deviation, trade volume, position count, daily loss and signal age. Opening the panel enables nothing; enabling requires explicit values. Broker/margin/freshness/idempotency guards always apply. Advanced edits on active/paused subscriptions need explicit confirmation, ownership and unresolved-operation checks; cancellation saves nothing/status unchanged.
- Daily-loss automatic Stop/close is separately opt-in with limit and consent; disabling the limit disables auto-close. Calculation uses whole-account equity and subscription risk budget with disclosed cash threshold. No optional limit silently becomes a mandatory preset or retrospective resize.
- Manual exposure/volume changes, protection/entry-price and loss-close decisions retain contextual review and explicit action where required. Read-only preview changes no trade. Offer Keep current state/no order when appropriate; failed confirmation may already have been saved, so prompt state inspection rather than claiming no change. Do not infer a specific invalid SL/TP level from a generic broker rejection or automatically restore manually reduced exposure without consent.
- Monitoring separates automatic recovery, final skipped/rejected entry, unknown result and action-required intervention. Current banners concern current subscriptions; previous follow-up stays historical. Read/acknowledge never executes/resolves a trade. A known terminal rejected entry is historical rather than unknown ownership and must not alone block independent safe work. Preserve audit, exact evidence and accessible details/next steps.

## 5. Provider admission and account management

Four independent provider-owned, revisioned, strict-boolean settings default OFF in Copy settings. Preserve omitted settings for older clients and audit changes. Requirements apply across strategies, exempt source accounts and do not interrupt existing active copying. Manual Resume checks current policy; final activation/Resume transactions recheck bound policy/account/evidence.

| Requirement | Verified source and boundary |
| --- | --- |
| Real accounts only | Strict Trading `is_demo=false` passes, true blocks, absent/null/invalid stays unknown. Check new connection/autobind, Start/legacy activation and manual Resume; do not infer from names or stream markers. |
| Account linked to provider partnership | Exact selected full trading account in registered provider's signed filtered Client accounts report, not client affiliation/another account. No email/client-UID join. Reuse encrypted sign-in pair with separate verification consent and report-access check. Complete filtered absence differs from pending/malformed/partial/error evidence. Revision-bound membership≤30seconds; no per-trade lookup. Disabling removes verification connection/evidence, retains disclosed provider-login credentials. |
| Same currency as strategy | Fresh Trading currency of investor versus selected source; USD and cent currencies differ. Check strategy readiness/Start/legacy/manual Resume, not pre-strategy login/connection. Bind source/strategy IDs and both currencies. |
| Same account type as strategy | Equal final nonempty Trading `stream_id` code, ignoring server prefix; open-ended codes without guessed Pro/Cent labels/whitelist. Missing/stale cannot match. Keep derived product type distinct from real/demo; `is_demo` stays authoritative. Same strategy-dependent boundaries/binding as currency. |

The broker `is_demo` extension and `stream_id` suffix semantics are owner-confirmed conventions with recorded product evidence; do not claim a new independent broker-schema validation. Existing credentials/refresh remain separate from immutable identity proof.

Owner-scoped subscriber disconnect is an authenticated operator-assisted action, not a new menu button. Require ended subscriptions/no unfinished commands/jobs; delete working broker credentials, mark disconnected, fence in-flight refresh, revoke owner sessions, audit/wake executor to close gateway next tick. Preserve historical account/report/subscription/command/mapping/financial records and normal backup retention. Reject other owners/source accounts. Refresh cannot reconnect; explicit later key authentication can reuse history without starting copying. No broker trading write or historical backup erasure.

## 6. Reports and recorded financial evidence

- Investor has copying/subscription and explicit whole-account scopes with Closed deals, Costs, Copying quality and CSV. Provider has Strategy performance, anonymized/per-currency investor Copying results and Copying quality. Report attribution uses confirmed request/order/position links, never mere connection date or whole-account equity. Do not expose investor secrets/unrelated account data.
- Show recorded closed P/L/cumulative step result, observed balance/equity, period UTC summaries and methodology/coverage. Distinguish observed account performance, copying-only recorded result, partial history and absence of data. Do not infer subscription percentage returns from whole-account equity or complete-period returns from complete saved components.
- Signed native-currency period trading net = gross close P/L + posted commissions + swap/admin costs, at posting time, including fees on open positions. Exclude funding and non-trading `null_compensation`; preserve event-time equity-flow valuation guards. No tariff/current-FX reconstruction, repeated partial-close opening fee, or second equity/TWR deduction. `net_realized` remains unavailable rather than confusing period cash net with closed-position net.
- Deduplicate REST/WS by account+deal ID before pagination. Preserve original sparse money/currency and source versions; validate legacy zero-open-profit evidence without rewriting history. Missing/conflicting/unclassified/ambiguous fees withhold complete net/curve while known components remain visible.
- Costs may display missing component0 only with No amount reported/shown as0 disclosure; raw storage/CSV/calculations retain unknowns, and net is never zero-filled. Verified Zero/Raw omitted close commission is Included at opening only with dated nonconflicting same-account/same-position opening-fee evidence. Explicit close amount wins; preserve raw/effective commission and basis. History-refresh guidance does not guarantee recovery of old gaps.
- Copying quality uses close volume for explicit/partial closes, target volume for entry/placement, words for unsized full close and no fabricated lots for SL/TP/edit/cancel. Investor entry average needs confirmed broker-submitted single-position entry evidence. Distinguish Not executed/Not confirmed/Not recorded/Not applicable. Pending placement is not a fill. CSV preserves raw target volume and requested-volume/entry-price states with blanks for missing numerics. Preserve quality denominator meanings.

## 7. Cloud operation, owner console and handoff

- Deploy in recipient-owned Cloudflare account with new explicit Worker/origin/state/backup resources and independent private secrets. Preserve reference/other installations. API/executor run without Codex, browser or user's computer. Persistent state, durable write acknowledgement, revision fencing, encrypted backups and restore must survive restart without duplicate ambiguous dispatch. Container-local files alone are insufficient. Pin dependencies, keep documented storage/bridge limits consistent and provide deploy/update/backup/restore instructions.
- Separate owner console has independent password/session storage, rate limits, secure cookies and exact-origin mutations; changing panel password invalidates sessions. Show target/status, change invitation and support confirmed reset. Invitation override persists appropriately; invitation change does not reopen registration. Panel password survives application reset.
- Reset requires exact target, inventory/revision freeze, draining backups, explicit destructive confirmation/exposure acknowledgment, idempotent durable job, clearing app data/snapshots and verified resume/reopened provider registration. Reset sends no broker close/cancel; disclose loss of management and broker-terminal follow-up. Never run a production reset as acceptance/repair.
- Deliver English provider and investor guides from the first useful build, updated to implemented features, with separate role procedures, credential scopes, deployment-independent operation, limitations, recovery, reports and troubleshooting. Include short owner operation instructions. English guides are required; a Russian translation is optional unless separately requested. Do not claim an unavailable function through a guide or ship real accounts/secrets as examples.

## 8. Explicit exclusions and evidence limits

No multi-provider marketplace, provider self-service key rotation/recovery, multiple investor accounts per session, concurrent unfinished strategies on one account, saved-strategy arbitrary edit/delete, subscriber bulk management, messenger/native Share menu or proposed combined Trading results chart. Do not import one-off account disconnections, past reset actions, test account balances or test scripts as automatic build actions.

Current interface headings/navigation/controls must preserve meaning and reachable actions (including Copy settings, role-specific Subscription/Reports, review/confirmation, Show/Hide and keyboard/manual-copy fallback), not exact pixel measurements, original internal namespaces or duplicate old layout requirements. Multi-card layouts and long fields must remain usable at desktop/mobile sizes.

Reference product has substantial existing local, browser, scoped live and release evidence, not an independently proven full parity guarantee. Historical counts overlap and must not be summed. Scoped live Proportional/lifecycle and one natural bracket pass do not prove all SL-only/TP-only, natural pending fills or fault-injection combinations. Earlier failed/time-limited attempts remain historical, not permanent broker diagnoses. A new generated build must earn its own passed/failed/skipped results; synthetic success, authored adapter, public asset identity and local guide validation prove different things.
